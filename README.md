# Novel Updates page JSON

A Chrome and Firefox extension that turns the open Novel Updates series page into one JSON object, ready to paste into a series form.

It reads the page in your own browser, where you are already signed in and past the challenge. It does not log in, does not call any API, and sends nothing anywhere.

## Install (unpacked)

**Chrome / Edge**

1. Open `chrome://extensions`.
2. Turn on **Developer mode**.
3. **Load unpacked**, then pick this folder.
4. Pin the extension so the button stays visible.

**Firefox**

1. Open `about:debugging#/runtime/this-firefox`.
2. **Load Temporary Add-on**, then pick `manifest.json`.
3. A temporary add-on disappears when Firefox restarts; load it again.

## Use it

1. Open a series page on Novel Updates, for example `https://www.novelupdates.com/series/example-series/`.
2. Click the extension button. It shows the title and how many genres and tags it found.
3. Press **Copy JSON**.
4. Paste it into whatever form reads the `nu.series.page/1` payload.

Nothing is saved anywhere until the form you paste into submits.

## The payload

One object, `schema: "nu.series.page/1"`:

| Key | From the page |
|---|---|
| `source_url` | the series slug in the address bar |
| `title` | `div.seriestitlenu` |
| `alt_titles` | `#editassociated`, split on `<br>` |
| `description_html` | `#editdescription`, forwarded as the page holds it |
| `raw_type`, `raw_language` | `#showtype a`, `#showlang a` |
| `raw_status` | the parenthesised word in `#editstatus` |
| `release_year` | `#edityear`, refused when it is in the future |
| `genre_names`, `tag_names` | `#seriesgenre a`, `#showtags a` |
| `cover_url` | `div.seriesimg img`, forced to https |
| `nu_series_id` | the `postid-<n>` class on `<body>` |

Names stay in Novel Updates' own vocabulary: the consumer maps them to its own ids, so the extension never guesses a local id. Caps are the consumer's: 512-character title, 20 alternative names, 100 genres, 100 tags, 200 KB of synopsis.

`description_html` is deliberately not sanitized here. The server that stores it owns that allowlist, and a second sanitizer in a client would drift.

## Build

```bash
npm run build
```

Stages `manifest.json`, `src/` and this README in `dist/`, which is what the release workflow zips. A tag `v*` publishes it as a GitHub Release.

## Test

```bash
npm install
npm test
```

The fixture is a hand-written page carrying the same markup a real series page carries, so no third-party content is redistributed. `tests/fixtures/series-page.expected.json` is generated by the consumer's server-side parser from that same fixture: when a selector moves on one side, a test goes red instead of half a payload shipping.

## Limits

- Unpacked only. There is no store listing, so nothing updates itself.
- Reads the active tab and nothing else: no host permissions, no background worker, no storage, no telemetry.
- A challenge page or a non-series page produces no JSON, and the popup says so.
